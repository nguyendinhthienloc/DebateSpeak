## 6. Key Risks and Mitigation

### Risk 1: Frontend-backend contract mismatch
- Mitigation: Define the room/session API contract before full UI implementation.
- Action: Tài and Triết will align endpoint names, payload fields, and response structure early.

### Risk 2: Scope drift from documentation to implementation
- Mitigation: Keep the sprint centered on FG-03 only and not expand to other functional groups.
- Action: The team will treat T3.4 as the main implementation priority.

### Risk 3: Documentation delays
- Mitigation: Finalize documentation in parallel with implementation instead of waiting until the end.
- Action: Lộc and Tuấn will maintain document updates during the sprint.

### Risk 4: Video demo quality and communication issues
- Mitigation: Prepare a short, clear walkthrough script and review the demo before submission.
- Action: Triết will prepare the narrated demo with team review.

---

## 7. Team Decisions
- Focus on one complete functional slice rather than partial work across multiple FGs.
- Treat the use-case model and specifications as the source of truth for functionality.
- Frontend and backend work must be aligned by a shared contract before late-stage integration.
- All final sprint artifacts must be reviewed by a human team member before submission.
- AI usage will be logged as support for idea generation and documentation clarification only, not for core implementation.
